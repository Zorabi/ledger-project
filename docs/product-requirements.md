# 礼尚往来项目产品需求

## 产品目标

本项目用于记录家庭场景下的礼尚往来信息，支持多个家庭以租户形式独立使用。系统应兼顾 Web 端和手机端，核心目标是高效录入、查询、统计、备份和恢复礼金/礼品往来数据。

## 租户与角色

- 系统采用家庭租户模型，一个用户只属于一个家庭。
- 所有家庭业务数据必须带 `family_id`，并在后端按登录用户所属家庭隔离。
- 家庭和家庭管理员只能由 `super_admin` 创建。
- 第一版使用单个 Vue 3 前端，按角色控制菜单、路由和页面权限。

角色定义：

- `super_admin`：系统管理员，管理所有家庭、家庭管理员、系统预置字典、系统配置，可代家庭执行备份导入。
- `family_admin`：家庭管理员，管理本家庭成员、对象、家庭字典、记录、统计、备份配置和导入恢复。
- `member`：家庭成员，可录入和查看本家庭授权范围内的礼尚往来数据。

## 认证与会话

- 不允许用户自行注册，用户账号由管理员创建。
- 第一版只支持账号密码登录。
- 密码必须哈希存储，推荐 bcrypt 或 argon2。
- 密码复杂度要求：至少 10 位，必须包含大写字母、小写字母、数字和特殊字符，不允许空白字符。
- 管理员创建用户时生成初始密码，前端应支持一键生成和复制初始密码。
- 用户首次登录必须修改密码。
- 支持管理员重置密码、禁用用户；不提供用户主动发起的“忘记密码/找回密码”入口，忘记密码必须由管理员核验后重置临时密码。
- 多次登录失败需要按账号和访问 IP 维度临时封禁，避免长期密码爆破；默认 15 分钟窗口内失败 5 次封禁 30 分钟，封禁和失败记录需定期清理。
- 登录失败、登录封禁、管理员重置密码均需写入审计日志。
- 使用 Access Token + Refresh Token。
- `access_token` 建议有效期 2 小时，`refresh_token` 建议有效期 30 天。
- 后端使用 `user_sessions` 管理 refresh token 哈希。
- 用户退出登录时废止当前 session。
- 用户改密或被禁用时废止全部 session。
- `user_sessions` 每日定时清理过期 session，以及已撤销超过 7 天的 session。

## 版本管理

- 后端配置中维护应用名称和版本号。
- 版本号使用 `X.A.B.C` 四段式格式：`X` 为主版本号，用于重大或不兼容变更；`A` 为次版本号，用于新增功能模块；`B` 为迭代号，用于已有功能迭代；`C` 为补丁号，用于 bug 修复、文档修正和发布规则修正等兼容小改动。
- 每次代码提交都必须按本次提交的最高影响级别同步更新应用版本号，并在 `CHANGELOG.md` 新增独立版本段。
- `CHANGELOG.md` 每个版本段只记录本次提交相对上一提交的实际差异，不记录对话过程、意图协商或未进入仓库 diff 的内容。
- 前端登录页和主界面应展示当前版本号，便于问题排查和发布验收。
- 后端提供公开版本接口，返回当前应用名称和版本号，不暴露敏感运行信息。
- 涉及数据库表结构、索引、字段或预置数据的版本必须提供对应 SQL 目录，目录格式为 `sql/<version>/001_ddl.sql` 和 `sql/<version>/002_data.sql`。

## 部署与运维

- 项目必须提供 `README.md`，说明本地启动、Docker 部署、共享 PostgreSQL 实例部署、数据库升级和服务器迁移流程。
- 项目必须提供 `Makefile`，封装本地开发、测试、构建、SQL 执行、数据库备份和恢复等辅助操作，但生产环境不依赖 `Makefile`。
- 生产环境支持手动数据库迁移模式，可关闭自动建库和自动迁移，由管理员按版本 SQL 执行 DDL 和 data。
- 共享数据库场景推荐共享 PostgreSQL 实例但使用独立业务 database，不建议与其他项目共用同一个 database。
- 生产数据库通常不允许开发机直连，SQL 执行、备份和恢复说明必须以 `psql`、`pg_dump`、`pg_restore` 原生命令和 DBA 执行路径为主，并支持在应用服务器、堡垒机、CI/CD 内网任务、DBA 工作台或 SSH 隧道环境中完成。
- 服务器迁移必须保留数据库备份、运行配置、`APP_ENCRYPTION_KEY` 和必要的 JWT/email 邮件配置。

## 核心业务

### 往来流水

核心数据采用“一条往来一条流水记录”模型。每条记录至少包含：

- 所属家庭
- 往来对象
- 事项类型
- 收礼/送礼方向
- 金额
- 礼品说明
- 发生日期
- 经办人
- 备注
- 回礼状态

金额按人民币处理，数据库以“分”为单位存整数，例如 `amount_cents BIGINT`。

### 往来对象

“对象”独立维护为往来对象表，不只是记录上的文本字段。

对象信息建议包括：

- 所属家庭
- 归属成员：可选，用于说明该对象主要属于家庭中的哪位成员的人情关系。
- 姓名/名称
- 对象类型：个人、家庭、单位等
- 关系类型：亲戚、朋友、同事、同学、邻居等
- 手机号
- 地址
- 备注
- 状态

用户账号和往来对象完全分开维护。

### 回礼管理

第一版只做手动回礼管理，不做自动复杂匹配。

记录支持：

- `none`：无需回礼
- `pending`：待回礼
- `done`：已回礼
- 可选 `related_record_id` 手动关联某条相关记录

关联规则：

- 送礼与回礼需要区分“我方回礼”和“对方回礼”。
- 手动关联回礼记录时，只允许关联同家庭、同对象、相反方向的流水。
- 关联成功后，双方记录均更新为 `done` 并互相保存关联 ID。
- 取消关联、删除关联记录或更换关联对象时，被关联记录应清空关联 ID，并回到 `pending`。
- 往来流水应支持筛选“已回礼但未关联流水”的异常数据，便于补录或修正历史记录。

对象详情页应展示：

- 收礼合计
- 送礼合计
- 差额
- 待回礼记录
- 已关联记录

记录录入后直接生效，不做审批流程。

## 数据字典

采用统一数据字典模型。

字典类型示例：

- 关系类型
- 对象类型
- 事项类型
- 礼品类型
- 支付方式

字典规则：

- 系统预置字典由 `super_admin` 维护。
- 家庭管理员只能维护本家庭自定义字典。
- 家庭不能修改系统预置字典。
- 字典类型关闭“允许家庭自定义”后，家庭已有自定义项保留可读，但家庭管理员不能继续新增、编辑或删除该类型的自定义项。
- 同一家庭可见范围内，同一字典类型的 `value` 必须唯一，避免下拉选择、字段翻译和统计归类出现歧义。
- 下拉框数据由系统预置项和当前家庭启用的自定义项合并而成。

## 收送概览

收送概览采用“核心统计卡片 + ECharts 固定图表”，支持按时间范围查询，默认查询全部时间。

核心统计卡片：

- 累计收礼
- 累计送礼
- 净差额
- 往来对象数
- 记录总数

固定图表：

- 收送趋势折线图：根据查询跨度动态选择每日或月度粒度。查询结果跨度不超过 90 天时按日展示，超过 90 天时按月展示；默认全部时间按实际流水最早/最晚日期判断。
- 收礼/送礼对比柱状图
- 事项占比饼图
- 对象金额 Top 10 条形图
- 关系统计图
- 归属成员统计图：按往来对象归属成员汇总收礼、送礼和记录数，未维护归属成员时归为“未指定”。
- 成员对象分布图：按往来对象归属成员统计对象数量，归属关系维护后即可反映对象分布。

第一版不做复杂 BI、自定义拖拽报表或自定义图表配置。

## 礼金待处理分析

系统应在收送概览之外提供独立的礼金待处理分析入口，避免高频处理事项被埋在统计图表中。

礼金回收：

- 用于查看我方已送礼、对方仍未回礼或已回礼但未关联流水的记录。
- 展示待回收金额、待回收对象数、待回收笔数和最久等待天数。
- 展示待回收对象 Top 5、账龄分布、归属成员待回收、关系类型待回收。
- 待回收明细必须分页展示，支持按时间范围查询。

礼金送出：

- 用于查看我方已收礼、我方仍未回礼或已回礼但未关联流水的记录。
- 展示待送出金额、待送出对象数、待送出笔数和最久等待天数。
- 展示待送出对象 Top 5、账龄分布、归属成员待送出、关系类型待送出。
- 待送出明细必须分页展示，支持按时间范围查询。

工作台也应支持相同时间范围筛选，并联动统计卡片和最近流水。

## 备份、导出与导入

### 导出备份

备份采用家庭级完整 Excel 导出。

导出内容：

- 往来流水
- 往来对象
- 家庭自定义字典
- 家庭成员基础信息，不导出密码哈希
- 统计摘要

导出文件应使用固定模板，便于后续按同格式导入恢复。

### 定时邮件备份

- email 邮件服务由系统统一配置。
- 备份收件人和频率按家庭配置。
- 频率支持每日、每周、每月。
- 第一版内置在 Go 后端进程中调度，不单独拆 worker。
- 调度任务应记录执行日志、发送状态和失败原因。

家庭备份配置建议包括：

- 是否启用
- 频率
- 收件邮箱列表
- 最近发送时间
- 最近发送状态
- 是否启用 ZIP 加密
- ZIP 密码提示

### ZIP 加密

- 备份邮件附件支持可选 ZIP 加密，默认关闭。
- 若启用加密，发送 `.zip`，否则发送 `.xlsx`。
- 邮件正文不包含密码，只包含密码提示。
- 使用服务端主密钥 `APP_ENCRYPTION_KEY` 加密保存家庭备份 ZIP 密码。
- 管理端不回显原密码，只允许重设。
- 如果未配置 `APP_ENCRYPTION_KEY`，不允许开启 ZIP 加密。

### 导入恢复

导入恢复分为“手工导入”和“备份恢复”两类能力。

权限：

- `family_admin` 只能导入恢复自己家庭。
- `super_admin` 可选择任意家庭代执行导入恢复。
- `member` 无导入权限。

导入策略：

- 第一版采用合并导入，不清空覆盖。
- Excel 中已有业务编号的数据更新。
- Excel 中没有的新数据新增。
- 当前系统有但 Excel 没有的数据保留。
- 手工导入面向普通用户，只要求填写业务可理解的往来流水和可选往来对象信息，不要求填写业务编号、对象编号、用户编号、字典编号等技术字段。
- 备份恢复面向系统完整备份文件，按导出文件格式识别编号、字典类型、数据字典、家庭成员等高级字段；不兼容旧版备份工作表命名。
- 导入前必须执行导入校验，展示新增、更新、冲突、错误数量；校验阶段不写入业务数据。
- 手工导入模板可直接用于新增数据，往来流水中对象名称存在时，系统应按名称匹配对象；匹配不到时自动创建往来对象。
- 金额推荐填写“金额(元)”；为兼容历史备份，若文件中存在“金额(分)”且有值，应优先按分导入。
- 正式导入前强制生成当前家庭备份，并通过邮件发送给操作人和相关备份收件人。
- 备份邮件发送失败则中止导入，不提供强制跳过。
- 导入有审计和批次记录，但第一版不做一键回滚。

## 审计日志

第一版加入轻量操作审计日志。

建议记录：

- 登录成功/失败
- 创建/禁用用户
- 创建/编辑家庭
- 新增/编辑/删除往来记录
- 字典维护
- 导入校验
- 执行导入恢复
- 手动导出
- 定时备份发送结果

审计字段建议：

- 家庭 ID
- 操作人 ID
- 操作类型
- 资源类型
- 资源 ID
- 操作结果
- IP
- User-Agent
- 时间
- 简要详情 JSON

## 删除策略

核心业务数据默认软删除或禁用，不做物理删除。

- 家庭：禁用，不物理删除。
- 用户：禁用，不物理删除。
- 往来对象：软删除。
- 往来流水：软删除。
- 家庭自定义字典：禁用或软删除。
- 备份日志、审计日志：不允许普通删除。
- 系统预置字典：禁用，不删除。

## 附件策略

第一版只预留附件模型和扩展点，不正式开放上传功能。

约束：

- 附件不存数据库。
- 附件必须带 `family_id`。
- 后续启用时优先接对象存储，例如 MinIO 或 S3。
- 后续必须增加单文件大小、单记录附件数量、家庭总容量限制。

## 当前交互补充

- 刷新页面时保留当前菜单，不应强制回到工作台。
- API 请求按当前菜单按需触发；切换菜单时应重新获取当前页面所需的完整数据，避免使用过期缓存。
- 列表查询统一通过显式“查询”触发，查询按钮应做防抖处理，避免连续点击或重复触发造成多次请求。
- 家庭管理、用户管理、往来对象、往来流水、备份日志、导入批次和审计日志等列表应提供分页；常用业务列表应提供符合场景的筛选条件。
- Web 端优先使用表格、筛选区和分页；移动端优先使用卡片、分组表单、底部导航和适配后的图表。
- 移动端页面内容从顶部开始排列，不因数据较少而垂直居中。
- 非“往来对象”页面不展示全局“搜索对象、手机号”，避免无效入口。
- 日期、占位符、按钮和业务字段在前端使用中文展示；数据字典的 `value` 列保持原始值，不做中文翻译。
- 视觉风格应保持现代、清爽、专业，允许适度激进的品牌表达，但不得依赖粗重色条、过度圆角、过强渐变或无意义装饰制造“模板感”。
- KPI 指标应作为高频扫描信息展示，优先使用独立轻量信息卡，避免连体数据条、粗竖线和顶部装饰线等影响专业感的样式。
- 菜单、方向选择、按钮等选中态应通过背景、边框、文字色、状态点和轻阴影综合表达，不使用突兀的贴边色块作为唯一识别方式。
- 页面加载应提供明确但不打断操作的反馈；页面级切换优先使用骨架屏，按钮级提交使用按钮自身 loading 状态。
- 登录状态过期时应弹出明确提示，用户确认后清理本地登录态并回到登录页。
- PC 端侧边栏背景应始终铺满视口高度；移动端底部导航保持固定可达，并避免遮挡主要内容。
